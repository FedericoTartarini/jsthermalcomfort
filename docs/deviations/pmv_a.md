## Notes

- `src/models/pmv_a.ts` `pmv_a`: `_pmv / (1 + a_coefficient * _pmv)` is a product, a sum and a quotient, each correctly rounded in IEEE 754 doubles, so it has no executed-path site (ADR 0009); `_pmv` is `pmv_ppd_iso`'s pmv rounded to two decimals, as upstream's call takes `round_output`'s default, and the kernel's arithmetic is in `pmv_ppd_iso`'s Notes. `np.around` is the library's `round` (ADR 0019, whitelist item 7). In the parity data, all 573 finite `a_pmv` equal upstream's and 427 are NaN, as upstream's are (node v26.8.2). Where `1 + a_coefficient * _pmv` is 0, `a_pmv` is `Infinity`, as upstream's is `inf` (measured on 4.7.0: `tdb=30, tr=30, vr=0.1, rh=50, met=1.2, clo=0.5, a_coefficient=-1/1.61`); numpy's `RuntimeWarning` "divide by zero encountered in scalar divide" has no counterpart, nor has the kernel's "invalid value encountered in \_pmv_ppd_optimized" for a negative `vr`, which 128 parity cases carry (decision 86).
- `src/models/pmv_a.ts` `pmv_a`: `APMVInputs` receives no `limit_inputs` (`models/pmv_a.py:107-117`), but the inner call's `PMVPPDInputs` does, so upstream rejects a `limit_inputs` that is not a boolean ("limit_inputs must be a boolean (True or False).", measured on 4.7.0), as the parse does with the library's message (deviation \_shared-10). The inner call takes `units` as the parse returns it, cast to `PMVPPDInputs`' type, in the case the caller gave, and upper-cases it as upstream's does.
- `src/models/pmv_a.ts` `pmv_a`: the `vr` and `clo` notes' `:py:meth:` references to `pythermalcomfort.environment.v_relative` and `pythermalcomfort.clothing.clo_dynamic_iso` are code spans naming the functions (ADR 0025), which the library has in `environment` and `utilities`, and the example imports `clo_dynamic_iso` from `jsthermalcomfort/utilities`, where upstream imports it from `pythermalcomfort.clothing`. The example's `.. code-block:: python` option `:emphasize-lines: 9,12,14` has no counterpart in a TypeScript fence, which ADR 0025's example rewrite replaces it with. The rest of the docstring is kept verbatim, the `wme` entry's "default is 0." included.
