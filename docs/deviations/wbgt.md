## Notes

- `src/models/wbgt.ts` `wbgt`: upstream's arithmetic is float64 multiplication and addition in upstream's order, which V8 computes alike (ADR 0009). On 100,000 cases drawn from `twb` in [-30, 45) °C and `tg` in [-30, 90) °C (numpy's `default_rng(42)`), half of them with `tdb` from [-30, 60) °C and `with_solar_load` true, half of the values rounded to one decimal, and 392 chosen points (`twb`, `tg` and `tdb` each -50, 0, -0.0, 5e-324, 25, 1e300 and -1e300 °C, with and without solar load), the unrounded `wbgt` equals upstream's bit for bit on all 100,392, and the rounded one equals on all (numpy 2.5.4 in the parity image, node v26.8.2). In the parity data, all 1,000 cases are bit-identical.
- `src/models/wbgt.ts` `wbgt`: upstream's `np.asarray(twb)`, `np.asarray(tg)` and `np.asarray(tdb) if tdb is not None else None` have no counterpart, since the model takes scalars (ADR 0019, whitelist item 8), and `np.round` is `round` (item 7). Upstream's `if with_solar_load:` (`models/wbgt.py:85`) reads `with_solar_load && tdb !== null`, which TypeScript narrows `tdb` by; the one call it sends to the other branch, `with_solar_load` with no `tdb`, has already thrown (`:82-83`). `tdb` is a `numeric` entry whose default is `null`, upstream's `None` (decision 252), checked by the parse whether or not `with_solar_load` reads it, as `BaseInputs` checks it (measured on 4.7.0: `tdb="20"` without solar load raises `TypeError`).
- `src/models/wbgt.ts` `wbgt`: the summary's `:py:meth:` reference to `pythermalcomfort.models.phs` is `{@link phs}` (ADR 0025), since the library's `phs` is a model on the TypeDoc site; the Returns section's `:py:class:` reference is `{@link WBGT}`. The example's two calls reuse one `let result`, as upstream's reassign `result`.
