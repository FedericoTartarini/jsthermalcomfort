## Notes

- `src/models/pmv_e.ts` `pmv_e`: `met * (1 + _pmv * -0.067)` and `_pmv * e_coefficient` are products and a sum, each correctly rounded in IEEE 754 doubles and evaluated in upstream's order, so they have no executed-path site (ADR 0009); `_pmv` is `pmv_ppd_iso`'s pmv rounded to two decimals, as upstream's calls take `round_output`'s default, and the kernel's arithmetic is in `pmv_ppd_iso`'s Notes. `np.around` is the library's `round`, `np.where` a ternary, which, as `np.where`, keeps `met` where the first pmv is NaN, and `np.asarray(met)` (`models/pmv_e.py:122`) has no counterpart, since `met` is a `number` (ADR 0019, whitelist items 7-9). In the parity data, all 574 finite `e_pmv` equal upstream's and 426 are NaN, as upstream's are (node v26.8.2); numpy's `RuntimeWarning` "invalid value encountered in \_pmv_ppd_optimized" for a negative `vr`, which 125 parity cases carry, has no counterpart (decision 86).
- `src/models/pmv_e.ts` `pmv_e`: `EPMVInputs` receives no `limit_inputs` (`models/pmv_e.py:109-119`), but the inner calls' `PMVPPDInputs` do, so upstream rejects a `limit_inputs` that is not a boolean ("limit_inputs must be a boolean (True or False).", measured on 4.7.0), as the parse does with the library's message (deviation \_shared-10). The inner calls take `units` as the parse returns it, cast to `PMVPPDInputs`' type, in the case the caller gave, and upper-case it as upstream's do.
- `src/models/pmv_e.ts` `pmv_e`: the `vr` and `clo` notes' `:py:meth:` references to `pythermalcomfort.environment.v_relative` and `pythermalcomfort.clothing.clo_dynamic_iso` are code spans naming the functions (ADR 0025), which the library has in `environment` and `utilities`, and the example imports `clo_dynamic_iso` from `jsthermalcomfort/utilities`, where upstream imports it from `pythermalcomfort.clothing`; the `clo` note's `:sub:` roles stay as upstream writes them, as in `pmv_ppd_iso`'s TSDoc. The rest of the docstring is kept verbatim, the `tdb`, `tr` and `vr` entries' "default in [°C] in [°F]" included, and the example's printed 0.48 is what 4.7.0 and the library return.
