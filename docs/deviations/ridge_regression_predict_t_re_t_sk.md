## Notes

- `src/models/ridge_regression_predict_t_re_t_sk.ts` `RIDGE_REGRESSION_PREDICT_T_RE_T_SK_INFO.inputs.sex`: `sex` is `BaseInputs`' `choice_field` (`classes_input.py:80`), which `BASE_INPUTS_SEX` (`src/_internal/define.ts`) holds once and the entry references, as `pet_steady`'s does, and whose message `choiceFieldMessage` builds from `allowed` as Python's `repr` writes the list (`classes_input.py:183`, decision 141).
- `src/models/ridge_regression_predict_t_re_t_sk.ts` `_predict_temperature_simulation`: upstream's arithmetic is float64 multiplication, addition, subtraction and division in upstream's order, which V8 computes alike (ADR 0009). `np.dot(scaled_features[:, :6], …)` for one scenario's row sums its six products left to right from the first, measured equal bit for bit on 8,000 of 8,000 rows in the parity image (numpy 2.5.4 with its bundled OpenBLAS 0.3.34), so the library writes the sum out in that order; a batch of rows takes OpenBLAS's gemv, which differs from it in the last bit on 15 to 29 % of rows for 2 to 8 rows, and which the library, taking scalars, never runs (decision 268). On 20,000 cases drawn with numpy's `default_rng(42)` inside the limits, half of each value rounded to one decimal, `duration` 2 to 600 and half of them with `t_re` and `t_sk`, with `limit_inputs` and `round_output` false, every element of both series equals upstream's bit for bit (compared by the SHA-256 of their float64 bytes, node v26.8.2). In the parity data, all 1,000 cases equal upstream's in every element.
- `src/models/ridge_regression_predict_t_re_t_sk.ts` `ridge_regression_predict_t_re_t_sk`: upstream's `np.atleast_1d`, `np.broadcast_arrays`, `np.ravel`, `np.full_like`, `np.stack`, the broadcast `try` and the scalar branch's `.squeeze()` have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9; decision 268): each feature list is one scenario's row, and `np.where` of the validity mask is a ternary per element. `RidgeRegressionInputs(…)` is the parse, then `RidgeRegressionInputs.__post_init__`'s checks (`classes_input.py:849-910`) as inline throws with upstream's messages, in its order; its finiteness checks are the parse's, and its two broadcast checks have no counterpart. The baseline branch assigns `t_re` and `t_sk` their initial values, as upstream does. `.strip()` is `.trim()`, which changes nothing after the parse, since the parse takes `sex` only as `"male"` or `"female"` in some case.
- `src/models/ridge_regression_predict_t_re_t_sk.ts` `_scale_features`: upstream's function and `_inverse_scale_output` take an array of scenarios; each takes one scenario's row here, and the mirrored tests pass upstream's one-row cases as that row.
- `src/models/ridge_regression_predict_t_re_t_sk.ts` `ridge_regression_predict_t_re_t_sk`: the docstring's citation `[Forbes2025]_` links to `docs/references.md`, its `:py:class:` reference is `{@link PredictedBodyTemperatures}`, and its Notes section is `@remarks` (ADR 0025); the rest of the docstring is kept verbatim, Python's terms included ("numpy arrays", `Sex.male.value`). The module's docstring (`models/ridge_regression_predict_t_re_t_sk.py:1-6`), which no other model has, is kept verbatim as line comments above the imports, since the template gives the model file no tag for it.
- `src/models/ridge_regression_predict_t_re_t_sk.ts` `_check_ridge_regression_compliance`: upstream's docstring is kept verbatim, its "Five arrays" included; each value here is a number, and the function appends the rows to `warnings`.
