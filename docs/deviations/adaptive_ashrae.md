## Notes

- `src/models/adaptive_ashrae.ts` `adaptive_ashrae`: upstream's arithmetic is numpy's float64 `+`, `-` and `*` on 0-d arrays (`SLOPE * t_running_mean + INTERCEPT`, the bounds `t_cmf ± 3.5` and `t_cmf + 2.5 + ce`, `operative_tmp`'s `a * tdb + (1 - a) * tr`, `units_converter`'s conversions), each correctly rounded and in the library's order, so ADR 0009 has no site here. All 3,250 finite numeric outputs of the parity data's 1,000 cases are bit-identical to upstream's (pythermalcomfort 4.8.0, node v26.8.2).
- `src/models/adaptive_ashrae.ts` `adaptive_ashrae`: upstream's `np.asarray` calls and its `np.where` on `all_valid` have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9). `units_converter(tdb=tdb, tr=tr, tmp_running_mean=t_running_mean, v=v)` takes `from_units`' default, IP, which the library's positional call passes explicitly as `Units.IP`. The acceptability is upstream's `_as_flag` of two comparisons, NaN where `t_cmf`, `to`, `ce` or `v` is NaN, so it is a nullable `flag`.
- `src/models/adaptive_ashrae.ts` `adaptive_ashrae`: the `t_running_mean` note's `:py:meth:` reference to `pythermalcomfort.environment.running_mean_outdoor_temperature` is a code span naming the function (ADR 0025), since the library's `running_mean_outdoor_temperature` is in `environment`, a JavaScript file that no model calls and that is not on the TypeDoc site (ADR 0018). The note's "ASHRAE 55 2020", which `_internal/ashrae55.py:12` calls 55-2023, is kept as upstream writes it.
- `src/models/adaptive_ashrae.ts` `ASHRAEInputs`: `units` takes `Units.IP` or `"IP"` (ADR 0019, whitelist item 5). Upstream's `adaptive_ashrae(tdb=77, tr=77, t_running_mean=68, v=0.3, units=Units.IP)` raises `AttributeError: 'Units' object has no attribute 'upper'`, since its `Units` members are not strings; the library's `Units.IP` is the string `"IP"`.
