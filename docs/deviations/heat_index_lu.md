## Notes

- `src/models/heat_index_lu.ts` `_lu_heat_index_optimized`: upstream's kernel is a numba `@vectorize` ufunc calling `@njit` functions. numba lowers `(t / _T_C_K) ** ((_CPV - _CVS) / _RGASV)` and `** ((_CPV - _CVL) / _RGASV)`, whose exponents are floats, to the C library's `pow` (`real_power_impl`, `numba/cpython/numbers.py:832-841`, numba 0.68.0). It unrolls `ts**2` and `rs**5`, whose exponents are integer literals, into `ts * ts` and `rs * (rs * rs * (rs * rs))` (`static_power_impl`, `:251-313`). So the powers are `**` and those products. `math.exp` is the C library's `exp`, and `Math.exp` is V8's own (ADR 0009). Measured in the parity image: numba's `x**5` equals `x * ((x * x) * (x * x))` on all of 200,001 values from -0.05 to 0.2, and C's `pow(x, 5.0)` on 95,991; `x**2` equals `x * x` on all of 200,001 values from 0 to 1000, and `pow(x, 2.0)` on 199,852. The test set was 100,000 cases drawn with numpy's `default_rng(42)` (`tdb` from -60 to 80 °C; `rh` from 0 to 100 %, exactly 0 or 100 in 5 % of cases; half of each value rounded to one decimal) and 12 chosen points (`tdb` -273.15 °C at `rh` 0 and 50, `tdb` 0 °C at `rh` 0 and 100, 127 °C at 100 %, 700 °C at 0 %, among others). On all of them every unrounded and every rounded `hi` equals upstream's bit for bit (node v26.8.2). Yet on the first 1,000 of those cases, V8's `Math.exp` differs from the C library's `exp` on 3,004 of 36,990 distinct arguments. `Math.pow` differs from C's `pow` on 27 of 11,172 arguments with the exponent `(_CPV - _CVS) / _RGASV` and on 43 of 25,820 with `(_CPV - _CVL) / _RGASV`. `_bisect` returns a midpoint of its bracket, and it reads the residuals only through the signs of `fa * fb` and `fb * fc`. On 33 further points (`tdb` up to ±1e200 °C, `rh` up to ±1e300 %), each value and each message of heat_index_lu-3 equals upstream's. In the parity data, all 1,000 cases are bit-identical.
- `src/models/heat_index_lu.ts` `_P_CR`: upstream computes `_AREA`, `_HC_CORE`, `_P_CR` and `_LAT_HEAT` in CPython, `_P_CR` through `_pv_star.py_func`, so with the C library's `pow` and `exp`. Each of the nine derived module constants equals upstream's bit for bit (measured: `repr` of each on 4.7.0, node v26.8.2).
- `src/models/heat_index_lu.ts` `_residual`: inside upstream's `@vectorize` kernel, a float division by zero gives ±inf or NaN, as JavaScript's does, and raises no `ZeroDivisionError`. Measured on 4.7.0 with numba 0.68.0: `_ra(310.0, 1e200)` is 0.0, and `_residual(1, 310.0, 1e200, 0.0, 0.0387, 0.0)` called on its own raises `ZeroDivisionError`, while `heat_index_lu(tdb=1e200, rh=50)` raises heat_index_lu-3's "wrong initial interval in the root solver". A `@vectorize` function that returns an `@njit` function's `1.0 / x` returns inf for 0.0. The library therefore checks no divisor, where `two_nodes_gagge_ji`'s scalar kernel throws (deviation two_nodes_gagge_ji-4).
- `src/models/heat_index_lu.ts` `_find_eq_var`: numba's `max(a, b)` returns `a` unless `b > a`, and `min(a, b)` returns `a` unless `b < a`, so each is written as that comparison, as `two_nodes_gagge_ji`'s register Notes give them. NaN reaches `max(0.0, …)` for a `tdb` below -273.15 °C, where `_pv_star` raises a negative kelvin temperature to a non-integer power.
- `src/models/heat_index_lu.ts` `heat_index_lu`: upstream's `np.asarray(tdb)` and `np.asarray(rh)` have no counterpart, since the model takes scalars (ADR 0019, whitelist item 8). numba's `@njit` and `@vectorize`, and the `cast` around the kernel, have none either: the kernel is scalar functions (item 9). `_pv_star.py_func` and `_latent_heat_vap.py_func` are direct calls, under upstream's comment on them. `_bisect`'s keyword arguments are positional, in its signature's order. `np.inf` is `Infinity`, and a returned tuple is an array.
- `src/models/heat_index_lu.ts` `HILu`: the result type is the model's own, `OutputsOf<typeof HEAT_INDEX_LU_INFO>`, whose `stress_category` is `null`, upstream's `None` as decision 16 reads it (decision 279). `HI`, which `heat_index_rothfusz.ts` derives from `HEAT_INDEX_ROTHFUSZ_INFO`, types `stress_category` as `string | null`, so decision 122's shared `HI` does not apply. The inputs type is named after upstream's `HIInputs` (`classes_input.py:443`), which upstream validates the model with (`models/heat_index_lu.py:48`), with the model's qualifier, as `HISchoenInputs` is (decision 251). Upstream issue #314 (open on 2026-11-02) asks for a stress category for `heat_index_lu`; a release that adds one turns `stress_category`'s entry into a classifier (ADR 0016).
- `src/models/heat_index_lu.ts` `heat_index_lu`: the docstring's citation `[lu]_` links to `docs/references.md`, and its `:py:class:` reference to `HI` is `{@link HILu}`, the type the model returns (decision 279; ADR 0025). The rest of the docstring is kept verbatim, Python's terms and "the returned `HI` instance" included. The example prints `25`, which upstream prints as `25.0` (ADR 0019, whitelist item 12).
