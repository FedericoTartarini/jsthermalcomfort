## Notes

- `src/models/esi.ts` `esi`: upstream's arithmetic is float64 multiplication, addition and subtraction in upstream's order, which V8 computes alike, and `(0.1 + sol_radiation_global) ** (-1)`, which numpy computes on a 0-d array as the reciprocal. The library writes `1 / (0.1 + sol_radiation_global)` (ADR 0009): on the `sol_radiation_global` values of the 100,072 cases the next sentence describes, numpy's term equals `1 / (0.1 + x)` on every one, where V8's `(0.1 + x) ** -1` differs from it on 110. On 100,000 (`tdb`, `rh`, `sol_radiation_global`) drawn from [-40, 60) °C, [0, 100) % and [0, 1400) W/m² (numpy's `default_rng(42)`), half of them rounded to one decimal, and 72 chosen points (`tdb` -40, 0, 30 and 60 °C, `rh` 0, -0.0 and 100 %, `sol_radiation_global` 0, -0.0, 5e-324, 1e-300, 1400 and 1e300 W/m²), the unrounded `esi` equals upstream's bit for bit on all 100,072, and the rounded one equals on all (numpy 2.5.4 in the parity image, node v26.8.2); `x ** -1` would also give equal `esi` on all 100,072. In the parity data, all 1,000 cases are bit-identical.
- `src/models/esi.ts` `esi`: upstream's `np.asarray(tdb)`, `np.asarray(rh)` and `np.asarray(sol_radiation_global)` have no counterpart, since the model takes scalars (ADR 0019, whitelist item 8). `ESIInputs(…)` is the parse, then `ESIInputs.__post_init__`'s two range checks (`classes_input.py:428-434`) as inline throws with upstream's messages, as decision 238 keeps each `rh` check, and `np.any(rh < 0) or np.any(rh > 100)` is one comparison.
