## Notes

- `src/models/phs.ts` `_phs_optimized_scalar`: upstream's kernel runs under numba, which unrolls a power with an integer literal exponent into multiplications (`static_power_impl`, `numba/cpython/numbers.py`, numba 0.68.0), so `(t_cl + 273) ** 4` is `(x * x) * (x * x)` and `w_req**2` and `(2 - w_req) ** 2` are `x * x`, and lowers a float exponent to the C library's `pow`, which `**` stands for (`weight**0.425`, `height**0.725`, `v_r**0.6`, `abs(...) ** 0.25`); `math.exp`, `math.cos` and `math.sqrt` are the C library's, `Math.exp`, `Math.cos` and `Math.sqrt` V8's (ADR 0009). V8's `Math.exp` differs from glibc's `exp` by an ulp on about 3 % of the kernel's arguments (logged over seven parity cases, 2,700 calls), and the kernel's convergence tests (`<= 0.001`) can carry the ulp through the 480 minutes: in the parity data, 10,820 of the 11,000 outputs are bit-identical, every rounded output equals upstream's, and five unrounded cases (50, 140, 207, 358 and 775) differ by up to 3.3e-9 relative, so the parity entry's tolerance is `rel: 1e-8` (node v26.8.2). `const_t_eq`, `const_t_sk` and `const_sw`, which CPython computes with `math.exp` when the module loads, equal V8's.
- `src/models/phs.ts` `_phs_optimized_scalar`: numba's `max(a, b)` returns `a` unless `b > a`, and `min(a, b)` returns `a` unless `b < a`, as `two_nodes_gagge`'s register measures, so each is written as that comparison, not `Math.max` or `Math.min`, which differ on NaN. `range(1, duration + 1)` runs `duration` truncated minutes for a `duration` that is not a whole number, as `time <= duration` does (measured on 4.7.0: `duration` 1.5 and 1.99 give the outputs of 1, 2.5 those of 2), and the exposure times left at 0 take `duration` as given.
- `src/models/phs.ts` `phs`: upstream's `np.asarray` calls, `np.broadcast_arrays`, `np.ravel`, the reshapes and `_phs_optimized_array`, whose `prange` loop calls the scalar kernel per element, have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9): the model calls `_phs_optimized_scalar` once, with its keyword arguments in its positional order. `acclimatized = int(acclimatized)` is `Math.trunc`. The output dict is written in the order of the `PHS` dataclass, which `PHS(**output)` takes its fields in.
- `src/models/phs.ts` `phs`: upstream's `default_kwargs` hold 2004's `f_r`, `t_re` and `t_cr_eq`, which `overrides_2023` replaces for 2023 under the comment "override changed default kwargs for 2023 standard", and `kwargs = {**default_kwargs, **kwargs}` gives a caller's value precedence. `PHS_INFO.inputs` gives 2023's, the default edition's, so the model takes `PHS_DEFAULTS_ISO_7933`'s entry for the `standard` given where the caller left the key out, which for 2023 is the parse's own default; the comment has no line to precede. Upstream's `p_a_lower` and `met_range` are the edition's entry of `PHS_LIMITS_ISO_7933` (decision 160).
- `src/models/phs.ts` `phs`: upstream's own check on `model` (`models/phs.py:202-207`) runs in the parse, from `PHS_INFO.inputs.standard` (decision 160), in `INFO.inputs`' order, so after the inputs before it, where upstream checks it before `PHSInputs` (deviation _shared-9). The comment "basic physical validation for carry-over state (supports scalar and array-like)" is kept as upstream writes it, though the model takes scalars.
- `src/models/phs.ts` `phs`: the docstring's citations `[7933ISO2004]_` and `[7933ISO2023]_` link to `docs/references.md`, its `:py:class:` reference is `{@link PHS}`, its `.. note::` is `> [!NOTE]`, and the `model` entry is `inputs.standard` (ADR 0019, whitelist item 3) with its text verbatim; the rest of the docstring is kept verbatim, Python's terms included (decision 186), as is `_posture_to_code`'s, which describes the array branch the library leaves out. The `evap_load_wm2_min` entry calls the input an instantaneous rate in W·m⁻², and its value is added to the running sum and carried over from a previous call's `evap_load_wm2_min`, which the dataclass gives in W·min·m⁻²; `PHS_INFO` gives the input that unit. The Examples section imports `phs` twice, the TypeScript example once.
- `src/models/phs.ts` `phs`: upstream's trailing comments on `kwargs["evap_load_wm2_min"]`, "accumulated evaporative load per area (W·min·m⁻² when accumulated)", and on `kwargs["sweat_rate_watt"]`, "instantaneous regulatory sweat rate at skin, [W·m⁻²]" (`models/phs.py:277-282`), have no line to precede, since both values come from the parse's destructuring; the parameter entries in the TSDoc describe the two inputs.
