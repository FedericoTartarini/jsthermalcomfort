## Notes

- `src/models/adaptive_en.ts` `adaptive_en`: upstream's arithmetic is numpy's float64 `+`, `-` and `*` on 0-d arrays (`SLOPE * t_running_mean + INTERCEPT`, the bounds `t_cmf - 3.0` to `t_cmf + 4.0 + ce`, `units_converter`'s conversions) and `operative_tmp`'s ISO `np.sqrt`, each correctly rounded and in the library's order, so ADR 0009 has no site here. All 3,066 unrounded finite numeric outputs of the parity data's 1,000 cases are bit-identical to upstream's, and all 2,870 rounded ones equal (node v26.8.2).
- `src/models/adaptive_en.ts` `adaptive_en`: upstream's `np.asarray` calls and its `np.where` on `all_valid` have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9). `units_converter(tdb=tdb, tr=tr, tmp_running_mean=t_running_mean, v=v)` takes `from_units`' default, IP, which the library's positional call passes explicitly as `Units.IP`. The acceptability is upstream's `&` of two comparisons, `False` where `t_cmf` is NaN, so it is a plain boolean, not a masked one (ADR 0006).
- `src/models/adaptive_en.ts` `adaptive_en`: a negative `v` makes `operative_tmp`'s ISO `np.sqrt(10 * v)` NaN, so every acceptability is `False` with a finite `tmp_cmf`, as upstream's is; numpy's `RuntimeWarning` "invalid value encountered in sqrt" has no counterpart (decision 86). Upstream draft 09 reports it.
