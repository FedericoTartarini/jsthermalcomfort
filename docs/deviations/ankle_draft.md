## Notes

- `src/models/ankle_draft.ts` `ankle_draft`: upstream's `np.exp` runs on 0-d arrays through numpy, which calls the C library's `exp`, and the library's `Math.exp` is V8's own (ADR 0009); the rest of the line is correctly rounded. On the 1,000 parity cases, 926 unrounded `ppd_ad` values are bit-identical to upstream's, the others at most 2.9e-16 relative apart, on Node 26.8.2, and every rounded `ppd_ad` equals upstream's. `tsv` is the inner `pmv_ppd_ashrae`'s pmv, rounded as its `round_output` default rounds it, whose arithmetic its register notes.
- `src/models/ankle_draft.ts` `ankle_draft`: upstream's `np.asarray` calls, with the comment above them, "Convert lists to numpy arrays", have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9), and `np.all(np.isnan(v_limited))` is `Number.isNaN(v_limited)`. `units_converter(tdb=tdb, tr=tr, vr=vr, vel=v_ankle)` takes `from_units`' default, IP, which the library's positional call `units_converter(Units.IP, { tdb, tr, vr, vel: v_ankle })` passes explicitly, with upstream's keys. The acceptability threshold, `ppd_val <= 20`, stays inline, as upstream writes it.
- `src/models/ankle_draft.ts` `ANKLE_DRAFT_INFO`: `vr` is checked twice, on 0-2 m/s as `"vr"` and on 0-0.2 m/s as `"v_limited"` (`_internal/ashrae55.py:36, :104-105`); INFO gives the narrower (decision 79), and the 0-2 bound appears only in `"vr"` rows. `rh` and `v_ankle` have no applicability, as upstream checks neither.
- `src/models/ankle_draft.ts` `ankle_draft`: the `vr` and `clo` notes' `:py:meth:` references to `pythermalcomfort.environment.v_relative` and `pythermalcomfort.clothing.clo_dynamic_ashrae` are code spans naming the functions (ADR 0025), which the library has in `environment` and `utilities`; the `clo` note's reStructuredText roles are kept as upstream writes them, as `pmv_ppd_ashrae`'s are. The example prints the library's result, where upstream prints the dataclass.
