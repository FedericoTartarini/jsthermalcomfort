## Notes

- `src/models/_pmv_ppd_optimized.ts` `_pmv_ppd_optimized`: upstream's kernel runs under numba, which lowers `x**4` to `(x*x)*(x*x)` (`int_power_impl`, ADR 0009), so `(tra / 100.0) ** 4` (twice), `xf**4` and `xn**4` are written so. Measured with numba 0.68.0 in the parity image on 20,000 seeded arguments in [2.5, 3.5), the range of `xf`, `xn` and `tra / 100`: `(x*x)*(x*x)` equals numba's `x**4` on all 20,000 on Node 22.13.0, 22.23.4, 24.21.0 and 26.8.2, `Math.pow(x, 4)` on 9,887 (Node 24 and 26) and 9,763 (Node 22), `x*x*x*x` on 12,724. `np.abs(100.0 * xf - taa) ** 0.25` is numba's libm `pow`, kept as `Math.pow`, which equals it on 19,970 of 20,000 arguments in [0, 30) on Node 24 and 26 and on 18,664 on Node 22; `Math.sqrt(Math.sqrt(x))` equals it on 17,538. `np.exp` stays `Math.exp` (ADR 0009). On 100,000 seeded cases (tdb 5-40 °C, tr 5-50 °C, vr 0-1.5 m/s, rh 0-100 %, met 0.7-4.2 met, clo 0-2.2 clo, wme 0 or 0-1 met), the unrounded pmv equals upstream's on 97,780 on Node 24 and 26, the others at most 1.9e-14 apart, and on 97,299 on Node 22, at most 8.6e-14 apart; with `Math.pow` for every power it was 30,897 on Node 24 and 26.
- `src/models/_pmv_ppd_optimized.ts` `_pmv_ppd_optimized`: upstream's `max(hcn, hcf)` is a comparison, `hcf > hcn ? hcf : hcn`, not `Math.max`: numba's `max(a, b)` returns `a` when `b` is NaN (measured: `max(1.0, nan)` is 1.0, `max(nan, 1.0)` NaN), so a negative `vr`, whose `np.sqrt` makes `hcf` NaN, computes as `vr = 0` does, where `Math.max` would return NaN. pythermalcomfort 4.7.0's kernel gives 0.12393214675717237 for vr -0.1 and for vr 0 at tdb = tr = 25 °C, rh 50 %, met 1.2, clo 0.5.
- `src/models/pmv_ppd_iso.ts` `pmv_ppd_iso`: upstream's ppd, `100.0 - 95.0 * np.exp(-0.03353 * pmv**4.0 - 0.2179 * pmv**2.0)`, runs through numpy, whose float exponent is the C library's `pow`, so it keeps `Math.pow` (ADR 0009). On the 100,000 cases' pmv as 0-d arrays, `Math.pow(pmv, 4.0)` equals numpy's on 99,844 on Node 24 and 26 and on 90,040 on Node 22, against 50,161 for `(pmv*pmv)*(pmv*pmv)`, and `Math.pow(pmv, 2.0)` and `pmv * pmv` equal it on all 100,000. In the parity data, all 304 rounded cases with a finite pmv agree exactly, and of the 271 unrounded ones 267 pmv and 258 ppd are bit-identical, at most 4.4e-16 and 2.8e-14 apart (Node 26.8.2).
- `src/models/pmv_ppd_iso.ts` `pmv_ppd_iso`: the kernel's x⁴ moved the unrounded pmv by an ulp at some inputs, so the category tests' edge inputs, which had been roots of `Math.pow`'s pmv, were found again with the kernel above; pythermalcomfort 4.7.0 gives the same unrounded pmv at each. At the two inputs the tests had at pmv -1.0 and just above it (met 1.04, tdb = tr = 22.957876105377593 and 22.957876105377597 °C), upstream gives -1.0000000000000038 and -1.0000000000000027, category "none" for both; the earlier kernel gave those values on Node 22 and -1 and -0.999999999999999 on Node 24 and 26, because `Math.pow(4.528973408591927, 4)` is 420.7257401281929 on Node 22.23.4 and 420.72574012819297 on Node 26.8.2.
- `src/models/pmv_ppd_iso.ts` `pmv_ppd_iso`: upstream's own check on `model` (`models/pmv_ppd_iso.py:180-186`) runs in the parse, from `PMV_PPD_ISO_INFO.inputs.standard` (decision 160), in `INFO.inputs`' order, so before `units`, `limit_inputs` and `round_output`, where upstream checks those first, in `PMVPPDInputs` (deviation _shared-9): a call with both a wrong `standard` and a wrong `units` throws the `standard` message, where upstream raises the `units` one. `standard.toLowerCase()` stays in the body, as upstream's `model.lower()` does. The `standard` entry's "any other value raises a `ValueError`" is kept verbatim (decision 186), where the library throws `RangeError` (row pmv_ppd_iso-8).
- `src/models/pmv_ppd_iso.ts` `pmv_ppd_iso`: upstream's `np.asarray` calls and its `np.where` on `all_valid` have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9). `units_converter(tdb=tdb, tr=tr, v=vr)` takes `from_units`' default, IP, which the library's positional call `units_converter(Units.IP, { tdb, tr, v: vr })` passes explicitly, with upstream's key `v`.
- `src/models/pmv_ppd_iso.ts` `PMVPPDInputs`: `units` takes `Units.IP` or `"IP"` (ADR 0019, whitelist item 5), where upstream's `Units` members are not strings and `units.upper()` raises `AttributeError`, as `utci`'s register notes. The type is named after `PMVPPDInputs` (`classes_input.py:594`), which upstream's `pmv_ppd_ashrae` also validates with; that model's is `PMVPPDAshraeInputs` (decision 196).
- `src/models/pmv_ppd_iso.ts` `pmv_ppd_iso`: the `vr` and `clo` notes' `:py:meth:` references to `pythermalcomfort.environment.v_relative` and `pythermalcomfort.clothing.clo_dynamic_iso` are code spans naming the functions (ADR 0025), which the library has in `environment` and `utilities`.
