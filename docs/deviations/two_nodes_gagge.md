## Notes

- `src/models/two_nodes_gagge.ts` `_gagge_two_nodes_optimized`: upstream's kernel runs under numba, which lowers `x ** 3.0` and the builtin `pow(x, y)` to the `llvm.pow` intrinsic, the C library's `pow` (`real_power_impl`, `numba/cpython/numbers.py:832-841`, numba 0.68.0; its `static_power_impl` unrolls only an integer exponent, `:255-261`), so every power is `Math.pow`, and `math.exp` is the C library's `exp`, so `Math.exp` (ADR 0009). On 20,000 seeded argument sets fed to both kernels (tdb 5-50 °C, tr 5-60 °C, v 0-3 m/s, rh 0-100 %, met 0.7-4, clo 0-2, wme, body surface area, pressure, both maxima and `w_max` varied, a fifth with `calculate_ce`), all 18 outputs are bit-identical on 10,825 sets and the others are within 9e-12 relative, none beyond the parity tolerance; `((t_cl + tr) / 2.0 + 273.15) ** 3.0` written as two multiplications gives 8,009 (numba 0.68.0 in the parity image, node v26.8.2). In the parity data, all 6,984 outputs of the 388 rounded cases equal upstream's, and 6,978 of the 7,701 outputs of the 612 unrounded cases are bit-identical, the others at most 2.1e-13 apart; on Node 22.13.0 and 22.23.4 it is 6,737, with the same bound.
- `src/models/two_nodes_gagge.ts` `_gagge_two_nodes_optimized`: numba's `max(a, b)` returns `a` unless `b > a`, and `min(a, b)` returns `a` unless `b < a` (measured: `max(1.0, nan)` is 1.0, `max(-0.0, 0.0)` is -0.0, `min(1.0, nan)` is 1.0), so each is written as that comparison, not `Math.max` or `Math.min`, which differ on NaN and on signed zeros. `(x > 0) * x` multiplies numba's 0.0 or 1.0 by `x`, so it is `Number(x > 0) * x`, which keeps the -0.0 a negative signal gives, where a ternary would give 0. `not w_max` is `w_max === null \|\| w_max === 0`, Python's falsy values among the ones the kernel receives; a NaN `w_max` is truthy in Python and is used as given here too. Upstream's `round(t_skin - q_skin / h_d_s, 2)` runs as numba's `round_ndigits`, `rint(x * 100.0) / 1.0 / 100.0` (`numba/cpython/builtins.py:254-286`), which the library's half-even `round` equals.
- `src/models/two_nodes_gagge.ts` `two_nodes_gagge`: upstream's `np.asarray` calls and its `np.vectorize` have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9); the kernel's tuple is assigned to the same names in one destructuring, `w_max` included, as upstream's unpacking rebinds `w_max`. `_gagge_two_nodes_optimized_return_set` takes `position` as upstream's `@vectorize` signature does, a float64, and the model passes it `1`, so the `calculate_ce` path computes as standing whatever `position` is, and also ignores `max_skin_blood_flow`, `max_sweating`, `w_max` and `round_output`, as upstream does (measured: `calculate_ce=True` gives `32.316713448080286` for `position` 'sitting' and 'standing' alike).
- `src/models/two_nodes_gagge.ts` `two_nodes_gagge`: `GaggeTwoNodesInputs.__post_init__` checks `w_max` after `BaseInputs`' checks (`classes_input.py:722-740`); the library checks it in the body after the parse, which already rejects `True`, NaN and a list (deviations _shared-5, _shared-6 and _shared-7), so only the range test is left, with the comment that precedes it upstream.
