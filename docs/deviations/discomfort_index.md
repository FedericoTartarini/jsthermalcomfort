## Notes

- `src/models/discomfort_index.ts` `discomfort_index`: upstream's formula is float64 arithmetic on 0-d arrays, in the order upstream writes it, so the library's is the same arithmetic (ADR 0009). On 100,000 (`tdb`, `rh`) drawn from [-50, 130) °C and [0, 100) %, half of them rounded to one decimal, and 18 chosen points (`tdb` 21, 24, 27, 29, 32, 99, 14.5, -243.12 and 0 °C at `rh` 0 and 100), the unrounded `di` equals upstream's bit for bit on all 100,018, and so do the rounded `di` and every `discomfort_condition`, 4,583 of them NaN (numpy 2.5.4 in the parity image, node v26.8.2; measured before decision 310 returned a nullable output's NaN as `null`). In the parity data all 1,000 cases equal.
- `src/models/discomfort_index.ts` `discomfort_index`: upstream's `np.asarray(tdb)` and `np.asarray(rh)` have no counterpart, since the model takes scalars (ADR 0019, whitelist item 8). `discomfort_condition` is mapped from the unrounded `di`, as upstream's `_mapping(di, …)` is, so a `di` of 20.95 °C rounds to 21.0 and has "No discomfort". Upstream checks no `rh` range, so an `rh` below 0 or above 100 gives a `di`, as upstream's does.
