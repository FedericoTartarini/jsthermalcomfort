## Notes

- `src/models/pmv_athb.ts` `pmv_athb`: upstream's `np.power(10, …)` and `np.exp(…)` run numpy's float64 functions on 0-d arrays, the C library's `pow` and `exp`, where the library's `Math.pow` and `Math.exp` are V8's own (ADR 0009); the rest of the body is products, sums and quotients, each correctly rounded in IEEE 754 doubles and evaluated in upstream's order, and the kernel's arithmetic is in `pmv_ppd_iso`'s Notes. On 100,000 seeded cases (`tdb` 5-40 °C, `tr` 5-50 °C, `vr` -0.2-1.5 m/s, `rh` 0-100 %, `met` 0.7-4.2 met, `t_running_mean` -10-35 °C, `clo` `False` or 0-2.2 clo, half of them rounded to one decimal), `Math.pow` equals numpy's on 50,100 of the 50,170 calls with `clo` `False` on Node 24.21.0 and 26.8.2 and on 45,201 on Node 22.13.0 and 22.23.4, and `Math.exp` on 90,247 of 100,000 on all four; the unrounded `athb_pmv` equals upstream's on 98,670 (Node 24 and 26) and 95,220 (Node 22), at most 4.6e-12 and 4.0e-10 relative apart, and after `np.around(…, 3)` and the library's `round(…, 3)` all 100,000 agree on all four (numpy 2.5.4 in the parity image). In the parity data, all 1,000 `athb_pmv` equal upstream's (node v26.8.2); numpy's `RuntimeWarning` "invalid value encountered in \_pmv_ppd_optimized" for a negative `vr`, which 114 parity cases carry, has no counterpart (decision 86).
- `src/models/pmv_athb.ts` `pmv_athb`: `ATHBInputs` receives no `clo` (`models/pmv_athb.py:86`, `classes_input.py:306-323`), so upstream checks it nowhere and `None` or a string raises in the kernel ("ufunc '\_pmv_ppd_optimized' not supported for the input types", measured on 4.7.0); the parse checks it against `PMV_ATHB_INFO.inputs.clo` with the library's message (deviation \_shared-10). `if clo is False` tests `clo_adapted`, which holds `clo` there, so TypeScript narrows the value the kernel takes to a `number`. Upstream's `np.asarray` calls have no counterpart, since the model takes scalars (ADR 0019, whitelist items 8 and 9).
- `src/models/pmv_athb.ts` `pmv_athb`: `met_adapted` divides by `58.2` (`models/pmv_athb.py:95`) where `ts` multiplies by `met_to_w_m2`, 58.15 (`:111`, `utilities.py:20`); both stay as upstream writes them.
- `src/models/pmv_athb.ts` `pmv_athb`: the `vr` and `t_running_mean` notes' `:py:meth:` references to `pythermalcomfort.environment.v_relative` and `pythermalcomfort.environment.running_mean_outdoor_temperature` are code spans naming the functions (ADR 0025), which the library has in `environment`. The `@param` entries follow the Parameters section's order, `clo` before `t_running_mean`, where the signature and `PMV_ATHB_INFO.inputs` put `t_running_mean` first (`models/pmv_athb.py:11-19`). The example keeps upstream's comment "returns the PMV value", where 4.7.0 and the library print 0.206. The rest of the docstring is kept verbatim, the `clo` entry's "set to False" and "Defaults to False" included (decision 186).
