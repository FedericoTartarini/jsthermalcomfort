## Notes

- `src/environment/transpose_sharp_altitude.ts` `transpose_sharp_altitude`: upstream's `math.radians` and `math.degrees` run under numba, which lowers each to a multiplication by the constant `math.pi / 180` or `180 / math.pi` (`numba/cpython/mathimpl.py:388-406`, numba 0.68.0), as the library writes them. Upstream's `round(x, 3)` runs as numba's `round_ndigits`, `rint(x * 1000.0) / 1000.0` with ties to even (`numba/cpython/builtins.py:254-286`), which the library's half-even `round` equals; Python's correctly rounded builtin `round` does not run here (ADR 0009). numba's libm `sin`, `cos`, `tan`, `asin` and `atan` and V8's give different unrounded results on 81,608 of 500,000 calls (`sharp` drawn from [0, 180) and `altitude` from [0, 90), half of them rounded to one decimal; numba 0.68.0 in the parity image, node v26.8.2), and equal results on all 500,000 after the rounding to 3 decimals.
- `src/psychrometrics/p_sat_torr.ts` `p_sat_torr`: upstream's `np.asarray(tdb, dtype=np.float64)` has no counterpart, since the helper takes a number (ADR 0019, whitelist item 8), and its `np.exp` is the C library's, where the library's `Math.exp` is V8's own (ADR 0009). On 100,000 `tdb` drawn from [-50, 60) °C, half of them rounded to one decimal, the two equal on 90,620 and differ by at most 2.3e-16 relative on the others (numpy 2.5.4 in the parity image, node v26.8.2); at -273.15 °C upstream gives `9.699125053317318e+53` and the library `9.699125053317317e+53`.
- `src/_internal/brentq.ts` `brentq`: a line-by-line port of scipy 1.18.1's `brentq` (`scipy/optimize/_zeros_py.py`, `_zerosmodule.c` and `Zeros/brentq.c`), with scipy's BSD-3 notice (ADR 0026). It takes `f`, `a`, `b`, `xtol`, `rtol` and `maxiter` with scipy's defaults; `args`, `full_output` and `disp`, which no upstream caller passes, are left out, so a call that does not converge throws, as `disp=True` raises. scipy's `operator.index(maxiter)` rejects every float, 3.0 included, with Python's message; the port throws `TypeError` with the library's message, "maxiter must be an integer.", for a `maxiter` that is not an integer, since a JavaScript number has no integer type (ADR 0022). C's `MIN` macro and `signbit` are written as C defines them, not as `Math.min` and a sign test. Its messages are scipy's, with the caller's value as JavaScript writes it ("x=0" where scipy writes "x=0.0", ADR 0022) and scipy's own `_rtol` as scipy writes it (`8.88178e-16`). Run on scipy's recorded cases (10,800 random brackets over nine families of functions and 17 edge cases, scipy 1.18.1 x86_64 in the parity image, node v26.8.2), it returns scipy's root bit for bit, after evaluating `f` at the same points in the same order, on all 6,217 cases of the six families that call no libm function where scipy converged, throws `Error` on all 983 where scipy raised `RuntimeError`, and gives scipy's result or error class on all 17 edge cases; `tests/internal/brentq.test.ts` checks 30 of them, re-run on scipy in the parity image.
